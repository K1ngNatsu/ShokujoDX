# Plan: roadmap phase P8 (management and connectivity)

Date: 2026-10-23 · Status: Accepted. Milestones 1 to 7 done in software (audit: `docs/design/roadmap.md`, "Audit of P8"); exit test part 2 (the Topaz 20 reads the stick) is open.

## Goal

The user finds, opens and sends designs quickly (roadmap P8). The exit
test: a library of 1000 designs is searchable in less than a second, and
a design goes to a USB stick for the Topaz 20 in one action.

The exit tests of P2 and P3 (users, with the 0.1.0 test package), P5,
P6 and P7 (sew-outs) are still open. The owner started this phase on
2026-10-23, while the test users try the 0.1.0 build.

Sources for what each tool does: the public documentation of commercial
embroidery products, the public format notes of pyembroidery (MIT,
commit `c16d1b4`) and common practice, in our own words (clean-room
rule).

## Order

Each milestone ends with something a user can try.

| # | Scope | Exit test |
| --- | --- | --- |
| 1 | **Design library engine.** A new engine crate `emb-library` (ADR 0035). Library folders: a scan finds the designs in them and their subfolders (`.embproj` and the machine formats that the app reads). For each design an index entry: name, file, folder, format, file size and date, width and height, stitches, colors, trims, the thread names and colors, the machine, the notes. A thumbnail (PNG) of the stitches. The index and the thumbnails are kept in the settings folder; a scan reads again only the files that changed. Search: words (all must match) in the name, file, folder, notes, threads and format, and filters (`format:vp3`, `colors:<4`, `stitches:1000-5000`, `width:<100`, `fits:<hoop>`). Sort (name, folder, date, size, stitches, colors, format) and group (folder, format, colors, the smallest hoop it fits). A design list as CSV. `emb-cli library <folder> [search]`. | Unit tests; a library of 1000 generated designs: the search takes less than a second (the P8 exit test, part 1). |
| 2 | **Design library window.** A Library tab next to the canvas: the library folders (add, remove, scan again), a grid of thumbnails or a list with the numbers, the search box with the filters, sort and group. Open a design (double-click) or the selected designs; new from selected (a copy of a design as a new, unsaved design); show the file in File Explorer. Catalog print: a PDF with the thumbnails and their numbers. Export the design list (CSV). The scan runs in the background; the window stays usable. | A test library in the app: search, sort, group, open; the catalog PDF. |
| 3 | **Send to USB.** File > Send to USB (and a ribbon button): the design goes in the format of the machine profile (VP3 for the Topaz 20) to the USB stick that the user chose for the machine, in one action. The program lists the removable drives; the target (drive and folder) is kept for each machine. The file is read back after the write to check it. If no stick is there, the program says so. Designs with hoopings send all their files. Send selected designs from the library. Machine connections: only protocols with a public description; none is known for the Topaz 20, so this milestone does not add one (ADR 0036). | One action sends a corpus design to a stick that the Topaz 20 reads (the P8 exit test, part 2). |
| 4 | **Export queue.** Output design, batch output and send to USB run as jobs in the background, one after another. An Exports panel shows the jobs that wait, run and are done (with their files and errors); the history is kept between sessions; a done job can show its folder or run again. | Unit tests on the queue; the panel in the app. |
| 5 | **Embroidery clipart.** Save the selected objects as a clipart item (an `.embproj` with a thumbnail) in a clipart folder, with a name and keywords. A Clipart panel: search, the thumbnails, a drag or a double-click puts a copy into the design at the view center. Some built-in items from the corpus shapes. | A clipart item saved, found and put into another design. |
| 6 | **More machine formats.** From the public notes of pyembroidery: PEC write, and the readers and writers that it has and the app does not (for example U01, KSM, PCS, PCM, PCD, PCQ, INF color files, EXY, STX, MIT, GT, ZHS). Machine functions of the industrial formats where the format has them (speed, empty stitch and empty jump). VIP and CSD only if a public description is found. | A golden round trip for each new writer; each new reader reads a file that its writer made, or a test file made from the public notes. |
| 7 | **Cutter output and barcodes.** The appliqué outlines as SVG and DXF files for a cutting machine (the placement line, at real size, one path for each piece). Barcodes (Code 39 and Code 128) with the design name on the worksheet, so a library or a shop system can find the design from the paper. | The cutter files open in a vector program at real size; a barcode that a phone app reads. |

Then the exit test (roadmap P8 exit): the 1000-design search time, and
one action that sends a design to a USB stick that the Topaz 20 reads.

## Progress

| # | State | Notes |
| --- | --- | --- |
| 1 | Done in software | New engine crate `emb-library` (ADR 0035): `find_files` and `scan` (unchanged files keep their entries; changed ones are read again with a new thumbnail; entries and thumbnails of removed files go; a scan can stop and keep the old entries), `read_entry` (project files get their stitch plan with their machine), thumbnails of 160 px, the index as JSON (`Index::load` gives an empty index for a damaged or old file). `search`: words (quoted phrases), `format:`, `folder:`, `name:`, `machine:`, number ranges (colors, stitches, trims, width, height, kb), `fits:<hoop>` (straight or turned, 5 mm margin), `error:`; sort by 7 keys; group by folder, format, colors or the smallest hoop. `csv::design_list`. `emb-cli library <folder>... --search --sort --desc --index --list`. Exit test part 1 (`tests/thousand.rs`): 1000 generated designs in 5 folders and 4 formats; each search with sort and group takes about 1 ms (debug build); the first scan takes about 1 s, an unchanged scan 0.1 s. The 38 corpus designs (170 files with VP3, DST and PES) scan in 0.6 s in a release build. |
| 2 | Done in software | App (`library.rs`): a Library tab next to the Design tab (File > Design library, View > Library). Folders menu (add, remove, scan again); the scan runs in a thread with a progress line and Stop, at each start and after a change of the folders; the index and thumbnails are in the `library` folder next to the settings file. Thumbnails (cards with name, format and size; the hover box has all numbers, threads, machine and notes) or a list with columns (a click on a column title sorts). Search box with the filters of Milestone 1 (problems show in the tool row), sort (and the other way), group. Click, Ctrl+click, Shift+click; double-click or Open opens each design in a tab of its own; New from selected makes an unsaved copy ("name (new)"); Show in File Explorer; context menu. Catalog (PDF): the found designs, 20 on a page, made in the background (`emb_library::catalog`; also `emb-cli library --catalog`). Design list (CSV). Only the rows on the screen draw, and thumbnails load 24 in each frame, so a large library scrolls smoothly. The program starts on the tab (Design or Library) that showed last. Checked in the app with the 170 corpus files. The catalog PDF is checked by a layout test, not by eye. |
| 3 | Done in software; test on the Topaz 20 open | App (`send.rs`, ADR 0036): removable drives from `sysinfo` (disk part only; the one exception to rule 9 besides the UI stack). File > Send to USB, Design > Output > Send to USB and Send to…, and Send to USB in the Library tab (button and context menu). The first send opens a window (the removable drives with name and free space, a folder on the stick); the stick (by name, else by drive letter) and the folder are kept for each machine (`Settings::send_targets`), and the next send goes there at once. The format is the default of the machine profile. The checks of Export block a design outside the hoop; a design with hoopings sends a file for each hooping; library designs are converted to the format. Each file is written, flushed, read back and compared; too little space sends nothing; a replaced file is named in the message. No machine connection: no public protocol (ADR 0036). Tests use folders as sticks; the computer here has no USB stick, so the real write is open for the owner. |
| 4 | Done in software | App (`jobs.rs`): a queue of jobs (a closure that runs in a thread of its own, one job after another). Output design (the checks and the project file at once, so the design is saved; the other files in the job), batch output, Send to USB (the stick is kept for the machine when the job ends well) and the library catalog are jobs. The Exports tab (next to Sequence, Threads and Stitch list; its title shows the number of jobs in the queue) lists the jobs, newest first: waiting (Cancel), running, done (files, details, Show folder, Run again, Remove) or failed (the error; also a message box). The history (the last 100 ended jobs) is in `exports.json` next to the settings file; a job that did not end when the program stopped shows as failed. Run again works for Output design (as a batch of its project file), batch output and the catalog. Output hoopings stays a direct action (its files come from the hooping previews). The queue polls each frame, so jobs go on while their tab is hidden. |
| 5 | Done in software | App (`clipart.rs`): a clipart item is a project file in the `clipart` folder next to the settings file; the keywords are in its notes, so the library engine indexes it, makes its thumbnail and searches it (the index is in `clipart/.index`). The Clipart tab (next to Object Properties, Styles and Design info): search box, Save selection…, show the folder, read again; cards with a thumbnail and the name (the hover box has the keywords). A double-click or Insert puts a copy at the center of the view; a drag onto the canvas puts it at the drop point; one undo step, the threads come with the objects (matched by name and color), and the copy is selected. Save as clipart (Edit > Clipart, the tab) keeps the selected objects with their threads, centered on the origin; a name that is there already is refused. 8 built-in items (heart, star, ring frame, banner, arrow, leaf, diamond, wave border) go to `clipart/Built-in` at the first start; a deleted item does not come back while that folder is there. |
| 6 | Done in software | `emb-formats` (ADR 0037): PEC write (`pes::write_pec_file`) and U01 read and write (`barudan`), the same bytes as pyembroidery for the 38 corpus designs. New readers: DAT (Barudan or Sunstar), EXY (`dst`), FXY and GT (`dsz`), STX (`exp`), PHB and PHC (`pes`), and BRO, EMD, INB, JPX, KSM, MAX, MIT, NEW, PCD, PCQ, PCS, PCM, SPX, STC, ZHS, ZXY (`minor`); each one reads a sample file with the same stitches, commands and colors as pyembroidery. Thread color files INF, EDR, COL (`colors`): Output design writes them (an option), and a DST or other file with no colors opens with the colors of the color file next to it (`emb_library::read_machine_file`, also in the library and batch output). Speed: `StitchKind::Slow` and `Fast`, the object function Sew slowly (Object Properties), the stitch plan puts the speed changes around slow objects; only U01 writes them (a U01 file with speeds from pyembroidery reads and writes again with the same bytes); U01 and DAT files open with Sew slowly on the slow parts. Export: PEC and U01; a Barudan machine profile. Golden test: each corpus design reads back from U01 and PEC with the same stitches and colors. Left out: PMV (a sewing-machine stitch pattern), ART (no reader), VIP and CSD (no public description), penetrations and borers (no format). |
| 7 | Done in software | Cutter files (`emb_formats::cutter`): the cut line of each appliqué piece (the outline and its holes) at real size, in machine coordinates (the design rotation and hoop angle applied), as SVG (mm, one path for each piece with its name) or DXF R12 (mm, closed polylines on a layer for each piece). Digitize > Appliqué > Cutter file and File > Appliqué cutter file (the selected appliqué objects, or all); `emb-cli cutter`. Barcodes (`emb_render::barcode`): Code 39 and Code 128 (set B) of the file name at the top right of the production worksheet (an output profile choice, Code 128 by default; also in print preview and `emb-cli output --barcode`). All 107 Code 128 symbols and the Code 39 and Code 128 bar patterns of sample texts are the same as the python-barcode package makes. A phone scan of a printed sheet is open for the owner. |
