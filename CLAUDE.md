# CLAUDE.md

This file is a copy of the "Instructions for Claude Code" section of `docs/SPEC.md`. The spec is the source of truth. Update both files together.

Put this document in the repository as `docs/SPEC.md`. Copy this section into `CLAUDE.md` at the repository root.

**Rules:**

1. Read `docs/SPEC.md` before you start a task. If a task conflicts with the spec, stop and ask.
2. Work in one phase at a time. Do not add features from a later phase.
3. Do not decompile, disassemble or copy code, assets or file samples from closed-source embroidery products.
4. When you port an algorithm from Ink/Stitch or pyembroidery, add a header comment with the source file path and the commit hash.
5. Keep engine crates free of UI dependencies. Do not add a dependency from a lower crate to a higher crate.
6. Use mm as `f64` everywhere outside `emb-formats`.
7. Add or update tests with each change. Do not update a golden snapshot without a note in the commit message that says why the output changed.
8. Run `cargo fmt`, `cargo clippy -- -D warnings`, and `cargo test --workspace` before each commit.
9. Do not use `unsafe` code. Each crate has `#![forbid(unsafe_code)]`. Engine crates (`emb-geom`, `emb-model`, `emb-stitch`, `emb-formats`, `emb-render`, `emb-letter`, `emb-art`, `emb-library`, `emb-script`, `emb-sketch`) must not depend on C or C++ libraries through FFI. Normal pure-Rust dependencies are permitted. The UI stack (`eframe`, `winit`, `wgpu`) uses `unsafe` internally to talk to the operating system; ADR 0001 records this. The app also uses `sysinfo` to find USB sticks (ADR 0036). Record any other exception in `docs/adr/`.
10. Record each architecture decision as a short ADR in `docs/adr/NNNN-title.md`.
11. Write documentation and code comments in ASD-STE100 Simplified Technical English.

**First task:** Phase 0. Create the workspace and the crate skeletons. Set up CI for three platforms. Load and validate `data/hoops.toml` and `data/machines.toml`. Build the undo/redo history and the native project format in `emb-model`. Build an egui prototype that shows a hoop outline and a pan-and-zoom canvas, and that draws a large synthetic stitch list to test speed. Write ADR 0001 with the UI framework decision.

- Letter corrections and font test sheets (ADR 0112): a letter of an embroidery font can be fixed (`EmbLetter::fixed`, `Letter::fixed`: the stitch engine sews its parts in the order of the font, each column from its start to its end; else it finds the order), and a part can have its own underlay, pull compensation and fill angle (`PartTuning`, applied by `Lettering::apply_params`); a new `Letter` literal needs both fields (`..Default::default()`). The corrections of a bundled font are `data/fonts/embroidery/corrections/<name>.json` (`emb_letter::correction`: a new shape, or the steps `order`, `reverse`, `join` on the converted letter); `tools/make-embroidery-fonts.py` applies them, so change a letter of a bundled font there, not in the `.embfont` file, then make the fonts again (a test checks it). The corrections of the user are the same files in `fonts/corrections` (`FontLibrary::corrections_dir`; the Alphabets window writes them: `place_letter`, `save_correction`). The test sheet is `emb_letter::sheet` (window `font_sheet.rs`, `emb-cli font-sheet`).
- Routed letters and tuned fonts (ADR 0113): all the embroidery fonts of the program and of the packages are made with `emb-cli font --extend --route` (ADR 0116); the ten fonts of `emb_letter::bundled::TUNED` (the same list as `TUNED` in `tools/make-embroidery-fonts.py`; `EmbFont::tuned`) also get `--tuned`: their letters were looked at on proof pictures. `emb_letter::tune` makes the ends of the columns reach the corners of the outline of the source font and gives round dots a column to their edge; `emb_letter::route` gives each letter the order and directions of its parts with the fewest trims, with travel runs (`ObjectKind::Running` parts) under the strokes that sew later, cuts of a column at a junction, and joins for script letters. A routed letter is fixed (ADR 0112), so code that reads the parts of a letter must accept runs. `emb-cli font-audit <font> --source <ttf>` measures a font (coverage of the outline, trims in the letters and in a sentence); `--proof` with `tools/font-proof.py` draws each letter. After a change of the stroke finder, of `tune` or of `route`: make all fonts again, audit them, and look at the proof pictures of the basic letters of the tuned fonts. A test that needs a font with no route converts a bundled TrueType font (`emb_letter::embfont::convert`): the sew order of the stitch engine does not change a routed letter, and the Mitre Corners setting joins only two columns of it that sew one after the other (`mitre::join_in_order`, ADR 0121; `mitre::join_parts` is for letters with no set order).
- Text shaping (ADR 0114): `emb_letter::shape::shape_line` shapes a line with `unicode-bidi` (runs and directions) and `harfrust` (glyphs; a port of HarfBuzz, no C code). A source of letters that shapes (`LetterSource::shape`: TrueType and OpenType fonts, not embroidery fonts) gives the layout its glyphs; one `Letter` is one cluster (a ligature, a conjunct, a base with its marks: `Letter::text` can have more than one character, and `Letter::index` is the index of its first character), and the letters of a line are in the order of the text (text from right to left sews from its right end). `Lettering::missing_characters` lists the characters that the font does not have. The bundled fonts for Arabic and Devanagari are `bundled::ARABIC` (Tajawal Bold) and `bundled::DEVANAGARI` (Poppins Bold); `icons::install_with` adds them to the fonts of the screen. `cargo run -p emb-letter --example shape_text` prints the glyphs of a text. After a new version of `harfrust` or of a bundled font, the test `the_test_texts_give_the_glyphs_of_the_reference` shows a change of a glyph: look at the sewn words before you write the new glyphs down.
- Quality score and font packages (ADR 0115): `emb_letter::quality` gives an embroidery font a score from 0 to 100 (shape covered, columns too narrow at the smallest size, stitches too long at the largest size; the letters and the digits). The converter makes it (`EmbFont::measure_quality` needs the source font) and the font file keeps it (`EmbFont::quality`); `emb-letter/build.rs` writes the table of the bundled scores (`bundled::quality`), and `FontEntry::score` is the score in the font lists. The score also counts the area of a letter outside its outline and the area with two layers (`quality::areas`, `LetterQuality::outside` and `overlap`, ADR 0119; not the trims), and a fill letter has the measures of a fill in each font (all of it too narrow in a font with a smallest size below 15 mm). With the stitch type Auto, the converter keeps the better of columns and fill for each letter (`EmbFont::choose_fills`, after the ends, the corrections and the route: the fill letter wins against the shape score of the columns, `LetterQuality::shape_score`); a new step that changes the columns goes before it. `emb-cli font-quality <font> --source <ttf> --letters` prints the measures of each letter and of its fill letter. Fill letters from a size (ADR 0120): a font with satin letters also has each letter as fills (`EmbLetter::fill_parts`, made last by `EmbFont::add_fill_letters`; not a fill font, not a font for small text) and `EmbFont::fill_letters` (`from_mm`, `min_mm`); the layout takes the columns up to `from_mm` and the fills above it, or what the stitch type of the lettering says (`EmbFont::uses_fill`; `LetterSource::fixed` and `tuning` get the stitch type and the scale). `EmbFont::max_height_mm` is then 300 mm, and code that needs the end of the columns (the score, the audit, the test sheet, the sew-out kit) uses `EmbFont::column_max_mm`, or the size range of the stitch type Satin. The converter also makes the size range fit the columns (`EmbFont::fit_size_range`). A font of the program has a score of `quality::LIMIT` (65) or more (a test checks it); a new font is in the program from `quality::BUNDLE` (85), else in a font package. `tools/make-embroidery-fonts.py` makes the fonts of the program and the packages (`data/font-packages/shokujodx-fonts-<name>.zip`, asset packages for File > My Assets > Import a package; the release workflow puts them in the release); its list says where each font goes, and it stops for a font below the limit. `bundled::EARLIER` are the four fonts of earlier versions that are in a package now. A font keeps its place (the program or its package) when a change of the converter changes its score, as long as the score is not below the limit (ADR 0116). Fill fonts (ADR 0117): a font with `EmbFont::fill` has all its letters as fills (the converter with the stitch type Fill, `--stitch fill`); its size range and its score come from the local widths of its letters and of their holes (`quality::fill_widths`), not from columns; the ten fill fonts of the program are the list `FILL` of `tools/make-embroidery-fonts.py` and the fonts of `bundled::EMBROIDERY` from `bundled::P17_EMBROIDERY` (`bundled::is_fill`, `FontEntry::fill`), with no route; a new fill font goes at the end of both lists, and the corpus design `embroidery-fonts-8` shows them.

- The surface (ADR 0124): `emb_render::strand::strands` (the stitches of a plan; `strand::lifts` gives the foam of puff objects from the spans of the plan) and `emb_render::surface`: `lay` lays the strands in sew order on a grid of 0.1 mm (a stitch is a taut thread over what is under its middle line, held at the fabric at its needle points; not on the stitch just before it; thread presses thread; foam is a floor), `Laid::surface` makes tiles of 256 pixels on all processors (each pixel depends only on the laid stitches: the same bytes on each system), and `surface::light` is the first light. `emb_cli::view::lay_design` lays a design; the bench writes `<design>-<zoom>-surface` pictures and the test `the_surface_has_the_heights_of_a_sew_out` reads the heights. - The light on the surface (ADR 0125): `Laid::surface` makes a surface at 16 pixels for each mm or more and halves it (`Surface::half`: means over the threads and over the fabric apart; the thread direction as a vector of two times its angle, shorter where directions spread); the shadows and the diffuse light are made at the detail for `Surface::light` (`Laid::surface_in` for another light). `emb_render::sheen::light` (`light_values` gives the linear light before the tone curve, `Light::picture` the colors): diffuse light, the sheen of fibers `TWIST_DEG` from the thread (`sheen_of` by kind), shadows, gaps, plies, a tone curve above white. The list of the ten engine crates is in four places (CI, `packaging.rs`, `i18n::ENGINE_CRATES`, `emb-geom/tests/determinism.rs`): a new engine crate goes in each. The numbers in the README are checked against the program (`packaging::the_numbers_in_the_readme_are_the_numbers_of_the_program`).
- egui sliders and number fields that show design values use `.clamping(egui::SliderClamping::Edits)` and `.clamp_existing_to_range(false)`, so drawing a panel never changes the design. `emb-app/src/smoke.rs` checks this for every corpus design.
- App commands live on the ribbon (`emb-app/src/ribbon/`, ADR 0010). A new command is a `Cmd` with `meta` (`commands.rs`), `can` and `run` (`run.rs`), placed in a tab panel (`tabs.rs`); `widgets.rs` draws the buttons and panels, `controls.rs` has the other controls of the panels. The files see each other through `use super::*` (items that more than one file uses are `pub(super)`). A command window (not a large dialog) goes through `crate::dock::docked` before `show`, so it docks at a corner of the canvas (ADR 0057). Command names, panel titles and menu items are in title case (ADR 0058); tooltips and messages are sentences.
- Toolset direction (consumer reference product study, Sequence panel, navigation keys): `docs/design/toolsets.md`. Describe the behavior of closed-source embroidery products in our own words only.
