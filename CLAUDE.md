# CLAUDE.md

This file is a copy of the "Instructions for Claude Code" section of `docs/SPEC.md`. The spec is the source of truth. Update both files together.

Put this document in the repository as `docs/SPEC.md`. Copy this section into `CLAUDE.md` at the repository root.

**Rules:**

1. Read `docs/SPEC.md` before you start a task. If a task conflicts with the spec, stop and ask.
2. Work in one phase at a time. Do not add features from a later phase.
3. Do not decompile, disassemble or copy code, assets or file samples from closed-source embroidery products.
4. When you port an algorithm from Ink/Stitch or pyembroidery, add a header comment with the source file path and the commit hash.
5. Keep engine crates free of UI dependencies. Do not add a dependency from a lower crate to a higher crate.
6. Use mm as `f64` everywhere outside `emb-formats`.
7. Add or update tests with each change. Do not update a golden snapshot without a note in the commit message that says why the output changed.
8. Run `cargo fmt`, `cargo clippy -- -D warnings`, and `cargo test --workspace` before each commit.
9. Do not use `unsafe` code. Each crate has `#![forbid(unsafe_code)]`. Engine crates (`emb-geom`, `emb-model`, `emb-stitch`, `emb-formats`, `emb-render`, `emb-letter`, `emb-art`, `emb-library`, `emb-script`, `emb-sketch`) must not depend on C or C++ libraries through FFI. Normal pure-Rust dependencies are permitted. The UI stack (`eframe`, `winit`, `wgpu`) uses `unsafe` internally to talk to the operating system; ADR 0001 records this. The app also uses `sysinfo` to find USB sticks (ADR 0036). Record any other exception in `docs/adr/`.
10. Record each architecture decision as a short ADR in `docs/adr/NNNN-title.md`.
11. Write documentation and code comments in ASD-STE100 Simplified Technical English.

**First task:** Phase 0. Create the workspace and the crate skeletons. Set up CI for three platforms. Load and validate `data/hoops.toml` and `data/machines.toml`. Build the undo/redo history and the native project format in `emb-model`. Build an egui prototype that shows a hoop outline and a pan-and-zoom canvas, and that draws a large synthetic stitch list to test speed. Write ADR 0001 with the UI framework decision.


## Project notes

- The program is **ShokujoDX** (ADR 0061; it was Ariadne, ADR 0059). Shown name `ShokujoDX`; technical id `shokujodx` (Linux program and app id, macOS bundle and file types `org.shokujodx.*`); Windows `ShokujoDX.exe` with the ProgIDs `ShokujoDX.Project` and `ShokujoDX.MachineFile`. The project file stays `.embproj`, and the crates stay `emb-*`. The settings folder is `workspace::program_folder` (a folder of an earlier name, `Ariadne` or `emb-digitizer`, moves there once; an `Ariadne` folder only if its settings file is ours).

- Architecture decisions: `docs/adr/`.
- All design changes go through `emb_model::Document::edit` (ADR 0004).
- Use `emb_geom::math` for trig functions in engine crates (ADR 0003).
- egui is 0.36: `eframe::App::ui`, `egui::Panel::left/right/top/bottom`. Check the source in the cargo registry before you use an API from memory.
- Scope reference is a leading commercial embroidery suite (the reference product): `docs/design/feature-inventory.md` (every feature with status and phase) and `docs/design/roadmap.md` (phases P1–P14). Update the status column when a feature lands.
- Export work (formats and stitch engine) follows `docs/design/export-plan.md`. Port sources: pyembroidery commit c16d1b4.
- Golden tests: `crates/emb-cli/tests/golden.rs` (corpus in `emb_cli::corpus`). To accept changed snapshots: `INSTA_UPDATE=always cargo test -p emb-cli --test golden`, then review the diff and say why in the commit message.
- Fill and satin stitches depend on the needle position (ADR 0007).
- Phase P2 work follows `docs/design/p2-plan.md` (seven milestones). Phase P3 work follows `docs/design/p3-plan.md` (eight milestones). Phase P4 work follows `docs/design/p4-plan.md` (seven milestones). Phase P5 work follows `docs/design/p5-plan.md` (seven milestones); stitch types are settings of the object kinds (ADR 0022). Phase P6 work follows `docs/design/p6-plan.md` (eight milestones); vector objects are an object kind with no stitches (ADR 0024). Border traces and linked shapes keep records that make their cuts again when objects move (ADR 0025, 0026): moves go through `Design::transform_objects` or call `Design::linked_objects_moved`. Auto-trace and click-to-stitch are in `emb_art` (ADR 0028); the Picture to design wizard (`emb-app/src/wizard.rs`) runs `emb_art::background`, `emb_art::cutout`, `emb_art::smart` and `emb_art::photo` (ADR 0029, 0030, 0031). Phase P7 work follows `docs/design/p7-plan.md` (six milestones); machine coordinates come from `Design::output_transform` only (the design rotation and the hoop angle, ADR 0032). Hoop width is left to right on the machine and the top of the canvas is the back of the machine; a turned hooping uses `hooping::TURN_DEG` (ADR 0034). Phase P8 work follows `docs/design/p8-plan.md` (seven milestones); the design library is the engine crate `emb-library` (ADR 0035). Phase P9 work follows `docs/design/p9-plan.md` (seven milestones; sequins, beads, chenille and Schiffli wait for a tester with such a machine); cross-stitch objects are an object kind with a cell grid and no paths (ADR 0038); rhinestone objects sew nothing and `Design::stones` places their stones with the overlap removal; the template takes its marks from the sewn marks object `Design::template_marks` (ADR 0039). Phase P10 work follows `docs/design/p10-plan.md` (nine milestones; Milestone 9, the assistant, is benched by the owner); the editing helpers are in `emb_model::editing` and `emb-app/src/editing.rs`; the 3D thread look is one shading model in `emb_render::thread3d` for the canvas meshes and the pictures (ADR 0040). Help topics are Markdown files in `docs/help` (in Simplified Technical English, built into the app by `emb-app/src/help.rs`); the topics of the ribbon tabs and of the keyboard are made from the ribbon, so a new command needs a clear tooltip. A new help file goes in `help::FILES`, with a `group` (start, tutorials, design, production, specialty, reference); a window with a help topic gets a row in `help::WINDOW_HELP`, so F1 over it opens the topic (ADR 0055). Each command is on the ribbon tab of its work (ADR 0055); the commands of one tab have different icons (a test checks it). Simple mode has its own ribbon panels (`ribbon::S_*`, large buttons, each command also on the full ribbon); the lettering kiosk (`kiosk.rs`) works on the design of its tab. Machine files go through `emb_formats::write_machine_with` with the machine profile (`AppState::machine_for_files` adds the user's trim settings) and the needle plan (`output::Catalogs::needle_plan`). Needles of multi-needle machines (ADR 0063): `emb_model::needles::assign` gives each color block a needle; pins are `Design::needles`, the threads on each machine are `Settings::needles`; TBF and U01 write the needles and a stop at each thread change; the window is `needles.rs`. A new bundled embroidery font goes in `tools/make-embroidery-fonts.py` (which makes all of them with `emb-cli font`) and in `emb_letter::bundled::EMBROIDERY` (compressed by `emb-letter/build.rs`), with its OFL text; a font with a Reserved Font Name gets a new name. Satin from shapes (ADR 0041): fills with a column stitch type sew in sections (`emb_stitch::textures::column_sections`, spacing across the stitches); spines and lines across a guide are in `emb_geom::spine`; Convert to satin uses a column only if `sews_well` passes, else a satin fill; direction lines are `FillParams::direction` and `SatinGeometry::with_direction`; Shortest order (Arrange > Sew order) is `emb_stitch::order`. Translations (ADR 0042): a new UI text goes through `crate::i18n::tr("…")`, or `crate::i18n::fill("… {} …", &[&v])` for values, then `UPDATE_LANG=1 cargo test -p emb-app i18n` makes `data/lang/template.toml` again; add the new texts to `data/lang/de.toml`, `es.toml` and `ja.toml` (a translation can drop a plural value with `{_}`); a label in a list gets `tr("…")` at its literal, and a name in a constant is shown with `tr(name)` and listed in `i18n::tests::engine_texts`; a button that the program paints or that has only an icon gets a screen reader name (`crate::a11y`). Packages (ADR 0043): `tools/package-windows.ps1 -Installer`, `tools/package-macos.sh`, `tools/package-linux.sh` (files in `packaging/`; no sample designs, so a new user starts with a clean slate, ADR 0080); a tag `v<version>` makes a draft release in CI (`.github/workflows/release.yml`); `crates/emb-app/src/packaging.rs` checks that the package files agree with the program; the icon is made by `tools/make-icon.py`. Phase P11 work follows `docs/design/p11-plan.md` (eight milestones; features of other programs, section 9 of the inventory); Ink/Stitch is GPL-3.0, so its algorithms can be ported with a header (rule 4); the other programs are closed source (rule 3). Thumbnails in the file manager (ADR 0046) all use `emb_library::preview`; the crate `emb-thumbnail` (the Windows COM handler) is the one crate with `unsafe` code, an exception to rule 9: keep its `unsafe` blocks small, with a `SAFETY` note. The density map is `emb_render::density` (layers of thread, ADR 0044) and the thread use `emb_model::thread_use`; `emb_cli::summary` makes the golden snapshots, so new numbers go in `emb_cli::production`. The fill types of P11 Milestone 4 (ADR 0047): a tartan or a gradient of several colors is a group of fills with the same shape, each with `FillPattern::Tartan` or `Gradient` and the number of its color, and each sews only its rows (`emb_stitch::fill::RowKeep`); `emb_model::tartan::tartan_layers` and `gradient_layers` make the settings, and the app window is `color_fills.rs`. Meander, circular, guided and ripple are in `emb_stitch::meander`, `rings` and `ripple`. Free-standing lace (ADR 0048): a design is lace if its fabric has the underlay weight `lace` (`Fabric::is_lace`) or it has a `FillPattern::Mesh`; the loose-part check is `emb_stitch::lace::loose_parts`; the lace templates are `emb_model::lace::TEMPLATES`. Quilting (ADR 0049) is `emb_model::quilt` (echo, background, block lines) and the app window `quilting.rs`; quilt blocks are lines, so P7 cuts them with no overlap and the joins align. Puff (ADR 0050) is `SatinParams::puff` (`emb_stitch::is_puff`); the plan puts the foam stop before the first puff object in a row; cap order is `emb_stitch::order::cap_order`, and cap frames have `HoopPreset::cap`. Cutwork (ADR 0051) is `emb_model::cutwork` (`RunningParams::cut`: no locks, a trim between parts; one object and color for each needle). Phase P12 work follows `docs/design/p12-plan.md` (three milestones; Picture to design robust and better). Decode pictures with `emb_art::decode_fit` (the wizard: `smart::decode_work`) and the budget `resources::decode_budget()`, and get their size with `emb_art::picture_size` (the EXIF orientation applied, ADR 0052); a texture that can be large goes through `resources::load_texture`, and engine work on picture data has no recursion (ADR 0077). The screen draws the stitch plan of `AppState::shown_plan` (a thread makes it; the last plan shows while a large one is made); export, output and commands use `AppState::plan_view` (the exact plan of the design as it is now). The wizard is a window state and a work state (`wizard::Work`, the settings and the results with quick keys); the previews after Background are made by a background job, so the step controls read results with the `ready_*` functions only. The steps that the wizard and the picture bench share are in `emb_art::smart` (`work_picture`, `detail_px`, `simplify`, `digitize`); `emb-cli bench` and the snapshot `bench__picture_bench.snap` measure the results (accept a change of it with a note, as for the golden snapshots). `digitize` sews small details on top (no hole), gives each fill the angle of its long axis (touching fills 30° apart) and makes small areas satins or runs (ADR 0053); the checks of the Finish step are `wizard::Check` with a `Fix`. Line art (thin, long, dark areas) sews last as runs or narrow satins, and any line under 1 mm is a run; Simplify has edge-preserving smoothing (`emb_art::adjust::smooth`) and colors from the thread chart (`reduce::reduce_with`; ADR 0054). Phase P13 work follows `docs/design/p13-plan.md` (four milestones; shop tools: quotes and run time, order details, thread stock, scripts; no customer database or invoices). Quotes and run times (ADR 0064) are `emb_model::quote` (`quote`, `run_time`; money in cents with `cents` and `money_text`); price lists are `Settings::price_lists`, the heads and hooping times are in `SewTimes`; the window is `quote.rs`. Order details (ADR 0065) are `Design::order` (`emb_model::order::OrderInfo`); change them with `AppState::set_order` (one undo step for each field); the window is `order.rs`; the sheets show `SheetData::order`, and the barcode uses `SheetData::barcode_text`. Thread stock (ADR 0066) is `Settings::thread_stock` (`emb_model::stock`); the threads in stock are also the chart `stock::STOCK_CHART`, last in `AppState::charts` (`refresh_stock_chart` after a change of the stock), so color matching takes the chart that shows (`AppState::chart`); the window is `stock.rs`. Scripts (ADR 0067) are Rhai in the engine crate `emb-script` (`run` on a copy; the app applies the result with one edit); a new script function goes in `emb_script::register` and in `docs/help/scripts.md`; the sample scripts are `data/scripts` (`emb_script::SAMPLES`); the window is `scripts.rs`. Phase P14 work follows `docs/design/p14-plan.md` (six milestones; parametric sketch mode). The sketch model and the solver are the engine crate `emb-sketch` (ADR 0068): a new constraint needs a `Constraint` variant, its check in `Sketch::check` and its equations in `equations.rs`; solve after each change (`Sketch::solve`, `drag`), and `analyze` for the free motions and the bad constraints. Sketch objects (ADR 0069) are `ObjectKind::Sketch` (`emb_model::sketch::SketchObject`: the sketch in its own coordinates and a placement; change it with `SketchObject::edit`, which makes the paths again). Sketch mode is `AppState::sketch` (`emb-app/src/sketch.rs`); change the open sketch with `AppState::edit_sketch` (one undo step; a drag merges); the Sketch tab (`RibbonTab::Sketch`) shows only in sketch mode. Drawing help and edits (ADR 0070): `emb_sketch::infer` (snaps and hints while drawing) and `emb_sketch::edit` (trim, extend, split, fillet, chamfer, offset, mirror, patterns, relax; each edit adds the constraints that keep it true); a refused edit goes through `AppState::try_edit_sketch` (no undo step), and a new refusal text goes in `edit::MESSAGES`. Sketch mode takes its keys in `sketch::handle_keys` before the keys of the program (ADR 0071); a length that the user types goes through `workspace::parse_length` (units, fractions and `+ - * /`). The sketch features of the reference CAD program (a leading parametric CAD program, the owner's choice) and their state are the table in `docs/design/p14-plan.md`; update it when one lands. Driven dimensions (`SketchConstraint::driven`) are not equations; `Sketch::add_dimension` makes a dimension driven when the sketch sets the size already; label places are `Sketch::label_at` (ADR 0072). Move, copy, rotate and scale of sketch parts are `Sketch::transform_parts`; a dimension from a point to a centerline is a diameter (the stored value); relax mode makes the dimensions driven during a drag (ADR 0073). Tangent circles, slot kinds, chamfer kinds, stretch, center points and `Sketch::auto_dimension` are ADR 0074; the constraint commands of the Sketch tab are a grid of icons (`ribbon::constraint_icons`) so the tab fits. The regions of a sketch are `Sketch::regions` (faces of the plane graph of its curves, ADR 0075); embroidery from them is `emb_model::sketch::region_objects` and `curve_objects`; the corpus design `sketch-badge` checks the whole way. Made objects keep a link (`Design::sketch_links`, ADR 0076): make them with `Design::make_from_sketch`, and call `Design::refresh_sketch_links` in the same edit as a change of the sketch (`edit_sketch` and `try_edit_sketch` do); a region is found again by its `RegionKey`. Parameters and expressions are `emb_sketch::params` and `emb_sketch::expr` (ADR 0078): change a parameter with `Sketch::set_parameter` (it applies the expressions; solve after it), and a template asks for the parameters of its sketches (`template::parameters`). Spline pieces are `Geometry::Bezier` (the handles are sketch points) and `Shape::Cubic`; a new match on `Geometry` or `Shape` needs them; drawings become sketches through `emb_sketch::import` (ADR 0079).
